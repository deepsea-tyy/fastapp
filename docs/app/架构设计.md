# FastApp 项目架构设计

## 概述

本项目采用**分层架构（Clean Architecture）**设计，遵循单一职责原则和依赖倒置原则，将代码分为三个核心层：Presentation（界面层）、Domain（业务逻辑层）、Data（数据层）。

**架构优势**：
- ✅ 各层职责清晰，便于维护和扩展
- ✅ 通过接口解耦，便于单元测试
- ✅ 业务逻辑独立，不依赖 UI 和数据源实现
- ✅ 支持多端（iOS、Android、Web）代码复用

## 二、分层架构设计

### 2.1 架构图

```
┌─────────────────────────────────────────────┐
│   Presentation Layer (界面层)                │
│   ┌─────────────┐      ┌─────────────┐     │
│   │  UI Widgets │      │ MobX Store  │     │
│   └──────┬──────┘      └──────┬──────┘     │
└──────────┼─────────────────────┼────────────┘
           │                     │
           └─────────┬───────────┘
                     │ 调用 UseCase
┌────────────────────▼─────────────────────────┐
│   Domain Layer (业务逻辑层)                   │
│   ┌──────────┐  ┌────────────┐  ┌────────┐ │
│   │  Entity  │  │ Repository │  │UseCase │ │
│   │  (实体)  │  │ (接口定义) │  │ (用例) │ │
│   └──────────┘  └──────┬─────┘  └────────┘ │
└───────────────────────┼────────────────────┘
                        │ 实现接口
┌───────────────────────▼────────────────────┐
│   Data Layer (数据层)                       │
│   ┌────────────────┐  ┌─────────────────┐ │
│   │ Repository实现 │  │  DataSource     │ │
│   │                │  │ (网络/本地/缓存) │ │
│   └────────────────┘  └─────────────────┘ │
└─────────────────────────────────────────────┘
```

### 2.2 各层职责

#### Presentation 层（界面层）

**职责**：
- UI 展示和用户交互
- 使用 MobX Store 管理页面状态
- 调用 Domain 层的 UseCase 处理业务逻辑
- 响应用户操作，更新 UI

**核心组件**：
- **Views**: Flutter Widget，负责 UI 渲染
- **Store**: MobX 响应式状态管理
- **DI Module**: 界面层依赖注入配置

**示例**：
```dart
// 用户登录页面
class LoginScreen extends StatelessWidget {
  final UserStore userStore = getIt<UserStore>();

  void _handleLogin() {
    // 调用 Store 方法，Store 内部调用 UseCase
    userStore.login(username: '...', password: '...');
  }
}
```

#### Domain 层（业务逻辑层）

**职责**：
- 定义业务实体（Entity）
- 定义仓库接口（Repository Interface）
- 封装业务逻辑（UseCase）
- 不依赖任何具体实现，保持纯业务逻辑

**核心组件**：
- **Entity**: 业务实体类（如 User、Order）
- **Repository Interface**: 数据访问接口定义
- **UseCase**: 业务用例，封装单一业务操作

**示例**：
```dart
// UseCase: 用户登录
class LoginUseCase {
  final UserRepository _repository;

  Future<User> call(LoginParams params) {
    return _repository.login(params);
  }
}
```

#### Data 层（数据层）

**职责**：
- 实现 Domain 层定义的 Repository 接口
- 处理网络请求、数据库操作、本地缓存
- 数据格式转换（API 响应 → Entity）

**核心组件**：
- **Repository Implementation**: 仓库接口实现
- **DataSource**: 数据源（网络 API、本地数据库、SharedPreferences）
- **API Client**: Dio 网络客户端

**示例**：
```dart
// Repository 实现
class UserRepositoryImpl implements UserRepository {
  final UserApi _api;
  final SharedPreferenceHelper _prefs;

  @override
  Future<User> login(LoginParams params) async {
    final response = await _api.login(params);
    await _prefs.saveAuthToken(response.token);
    return User.fromJson(response.data);
  }
}
```

### 2.3 依赖方向

```
Presentation Layer  →  Domain Layer  ←  Data Layer
     (界面层)            (业务逻辑层)      (数据层)
```

**依赖规则**：
- ✅ Presentation 层依赖 Domain 层
- ✅ Data 层依赖 Domain 层（实现接口）
- ❌ Domain 层不依赖任何层（纯业务逻辑）
- ❌ Data 层和 Presentation 层相互独立

**通过依赖注入（GetIt）解耦**：
```dart
// service_locator.dart
void setupLocator() {
  // 1. 注册 Data 层
  getIt.registerLazySingleton<UserApi>(() => UserApi());
  getIt.registerLazySingleton<UserRepository>(
    () => UserRepositoryImpl(getIt<UserApi>())
  );

  // 2. 注册 Domain 层
  getIt.registerLazySingleton<LoginUseCase>(
    () => LoginUseCase(getIt<UserRepository>())
  );

  // 3. 注册 Presentation 层
  getIt.registerLazySingleton<UserStore>(
    () => UserStore(getIt<LoginUseCase>())
  );
}
```

## 三、状态管理

### 3.1 Store 分类

#### 全局 Store
**位置**: `presentation/store/app/`

| Store | 职责 | 生命周期 |
|-------|------|----------|
| `UserStore` | 用户登录状态、用户信息管理 | 应用全局 |
| `ThemeStore` | 主题切换（深色/浅色） | 应用全局 |
| `LanguageStore` | 多语言切换 | 应用全局 |

#### 功能级 Store
**位置**: `presentation/store/{feature}/`

| Store | 职责 |
|-------|------|
| `HomeStore` | 首页状态管理 |
| `MarketStore` | 市场数据和行情管理 |
| `SpotStore` | 现货交易状态 |
| `FuturesStore` | 期货交易状态 |
| `OrdersStore` | 订单列表和管理 |
| `WalletStore` | 钱包资产和交易 |
| `ExKycStore` | KYC 认证状态 |

### 3.2 Store 使用原则

1. **全局 Store**: 多个页面共享的应用级状态
2. **功能级 Store**: 特定业务功能的状态管理
3. **页面级 Store**: 仅在单个页面使用，可放在页面目录下

### 3.3 Store 最佳实践

```dart
// ✅ 好的实践
class UserStore = _UserStore with _$UserStore;

abstract class _UserStore with Store {
  final LoginUseCase _loginUseCase;

  _UserStore(this._loginUseCase);

  @observable
  User? currentUser;

  @action
  Future<void> login(String username, String password) async {
    currentUser = await _loginUseCase.call(LoginParams(username, password));
  }
}

// ❌ 避免的做法
class UserStore {
  // 不要在 Store 中直接调用 API
  final UserApi _api;

  Future<void> login() async {
    final response = await _api.login(...); // ❌ 应该通过 UseCase
  }
}
```

## 四、网络层

### 4.1 网络客户端

统一使用 `core/data/network/dio/dio_client.dart` 作为网络客户端。

**配置**：
- 基础 URL: 从 `AppConfig.apiBaseUrl` 读取
- 超时配置: 连接、接收、发送超时
- 拦截器: 认证、日志、错误处理、Token 刷新

### 4.2 拦截器

| 拦截器 | 职责 | 位置 |
|--------|------|------|
| `AuthInterceptor` | 自动添加认证 Token | `core/data/network/dio/interceptors/` |
| `LoggingInterceptor` | 请求和响应日志记录 | `core/data/network/dio/interceptors/` |
| `ErrorInterceptor` | 统一错误处理和转换 | `core/data/network/dio/interceptors/` |
| `TokenRefreshInterceptor` | Token 过期自动刷新 | `core/data/network/dio/interceptors/` |

### 4.3 API 定义

所有 API 定义在 `data/network/apis/` 目录下，按功能模块分类：

```dart
// data/network/apis/user/user_api.dart
class UserApi {
  final DioClient _dioClient;

  Future<Map<String, dynamic>> login({
    required int type,
    String? username,
    String? password,
  }) async {
    return await _dioClient.post(
      Endpoints.userLogin,
      data: {'type': type, 'username': username, 'password': password},
    );
  }
}
```

## 五、本地存储

### 5.1 存储方案

| 存储类型 | 技术方案 | 使用场景 | 文档 |
|----------|----------|----------|-----|
| **键值存储** | SharedPreferences | 用户配置、Token、简单数据 |
| **结构化存储** | Sembast | 复杂数据、离线缓存 | - |

### 5.2 统一存储管理

项目使用 **`SharedPreferenceHelper`** 统一管理所有 SharedPreferences 存储。

**核心组件**：
- `Preferences` - 定义所有存储 key 常量
- `SharedPreferenceHelper` - 提供统一的读写接口

**快速示例**：

```dart
// 获取实例
final sharedPrefHelper = getIt<SharedPreferenceHelper>();

// 读取数据
final token = await sharedPrefHelper.authToken;
final deviceId = await sharedPrefHelper.deviceId;

// 写入数据
await sharedPrefHelper.saveAuthToken('token_xxx');
await sharedPrefHelper.saveDeviceId('device_xxx');

// 批量清理（退出登录）
await sharedPrefHelper.clearAllUserRelatedData();
```

**优势**：
- ✅ 统一管理所有 key，避免硬编码
- ✅ 类型安全，编译时检查
- ✅ 批量清理，退出登录一行代码搞定
- ✅ 易于测试和 Mock

## 六、依赖注入

### 6.1 GetIt 服务定位器

项目使用 **GetIt** 进行依赖注入，配置在 `lib/di/service_locator.dart`。

### 6.2 注册顺序

```dart
Future<void> setupLocator() async {
  // 1. Local Module（本地存储）
  await LocalModule.configureLocalModuleInjection();

  // 2. Network Module（网络层）
  await NetworkModule.configureNetworkModuleInjection();

  // 3. Data Layer（数据层）
  await DataModule.configureDataModuleInjection();

  // 4. Domain Layer（业务逻辑层）
  await DomainModule.configureDomainModuleInjection();

  // 5. Presentation Layer（界面层）
  await PresentationModule.configurePresentationModuleInjection();
}
```

### 6.3 注册类型

| 类型 | 方法 | 说明 | 使用场景 |
|------|------|------|----------|
| **Singleton** | `registerSingleton()` | 立即创建，全局唯一 | 数据库、网络客户端 |
| **LazySingleton** | `registerLazySingleton()` | 首次使用时创建 | Repository、UseCase |
| **Factory** | `registerFactory()` | 每次调用创建新实例 | Store（如需要） |

### 6.4 使用示例

```dart
// 注册
getIt.registerLazySingleton<UserRepository>(
  () => UserRepositoryImpl(getIt<UserApi>())
);

// 使用
final userRepo = getIt<UserRepository>();
```

## 八、开发流程

### 8.1 添加新功能的标准流程

```
1. Domain 层
   ├─ 定义 Entity (实体)
   ├─ 定义 Repository Interface
   └─ 创建 UseCase

2. Data 层
   ├─ 创建 API 定义
   ├─ 实现 Repository
   └─ 配置 DI

3. Presentation 层
   ├─ 创建 Store
   ├─ 实现 UI
   └─ 配置 DI
```

### 8.2 示例：添加订单功能

#### Step 1: Domain 层

```dart
// domain/entity/order/order.dart
class Order {
  final String id;
  final String symbol;
  final double price;
  // ...
}

// domain/repository/order_repository.dart
abstract class OrderRepository {
  Future<List<Order>> getOrders();
}

// domain/usecase/order/get_orders_usecase.dart
class GetOrdersUseCase {
  final OrderRepository _repository;

  Future<List<Order>> call() => _repository.getOrders();
}
```

#### Step 2: Data 层

```dart
// data/network/apis/order/order_api.dart
class OrderApi {
  Future<Map<String, dynamic>> getOrders() async {
    return await _dioClient.get(Endpoints.orders);
  }
}

// data/repository/order_repository_impl.dart
class OrderRepositoryImpl implements OrderRepository {
  final OrderApi _api;

  @override
  Future<List<Order>> getOrders() async {
    final response = await _api.getOrders();
    return (response['data'] as List)
        .map((json) => Order.fromJson(json))
        .toList();
  }
}
```

#### Step 3: Presentation 层

```dart
// presentation/store/orders/order_store.dart
class OrderStore = _OrderStore with _$OrderStore;

abstract class _OrderStore with Store {
  final GetOrdersUseCase _getOrdersUseCase;

  @observable
  List<Order> orders = [];

  @action
  Future<void> loadOrders() async {
    orders = await _getOrdersUseCase.call();
  }
}

// presentation/views/orders/orders_screen.dart
class OrdersScreen extends StatelessWidget {
  final OrderStore orderStore = getIt<OrderStore>();

  @override
  Widget build(BuildContext context) {
    return Observer(
      builder: (_) => ListView.builder(
        itemCount: orderStore.orders.length,
        itemBuilder: (_, index) => OrderItem(orderStore.orders[index]),
      ),
    );
  }
}
```

## 九、最佳实践

### ✅ 推荐做法

1. **遵循分层原则**: 不要跨层调用（如 View 直接调用 Repository）
2. **使用 UseCase**: 将业务逻辑封装在 UseCase 中，Store 只调用 UseCase
3. **统一存储管理**: 使用 `SharedPreferenceHelper`，不要直接用 `SharedPreferences`
4. **依赖注入**: 通过 GetIt 注入依赖，不要在类中 new 对象
5. **错误处理**: 在 Repository 层统一处理网络错误
6. **命名规范**: 遵循 Dart 命名规范，类名大驼峰，方法名小驼峰

### ❌ 避免的做法

1. **不要在 View 中写业务逻辑**: 业务逻辑应该在 UseCase 或 Store 中
2. **不要在 Domain 层引入 Flutter 依赖**: Domain 层应该是纯 Dart 代码
3. **不要硬编码**: 配置、颜色、字符串都应该定义在常量中
4. **不要绕过 Store**: View 不要直接调用 UseCase
5. **不要直接使用 SharedPreferences**: 使用 `SharedPreferenceHelper`
