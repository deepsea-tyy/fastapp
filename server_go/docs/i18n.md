# 国际化（i18n）

## 请求语言如何确定

全局中间件 **`middleware.Translation`**（在 [`translation.go`](../internal/app/middleware/translation.go)）读取 **`Accept-Language`**，经 [`i18n.NormalizeLocale`](../internal/app/i18n/i18n.go) 规范为：

- **`en`**：头以 `en` 开头（大小写不敏感，`-` 视作 `_`）
- **`zh_CN`**：其余情况（默认）

结果写入 Gin：**`c.Set(i18n.ContextLocaleKey, loc)`**，键名常量为 **`i18n.ContextLocaleKey`**（`"locale"`）。

## 在业务中取当前语言

- **`i18n.FromGin(c)`**：从 context 读 locale，缺省为 **`zh_CN`**。
- **`middleware.Locale(c)`**：与上一行等价（薄封装）。

## 词条与加载

核心词条在工程根 **`storage/locales/*.json`**（**`en`**、**`zh_CN`**）。`cmd/server` 启动时 **`i18n.Init`**（目录见 [`StorageLocalesDir`](../internal/app/common/paths.go)）读入内存；**`i18n.T(locale, key)`** 按语言取文案，**无则返回 key 本身**；英文缺条会**回退到 zh_CN**。

插件或启动逻辑可在运行期 **`i18n.Merge(locale, map[string]string)`** 合并额外词条（**后写入覆盖先前**）。`locale` 须为 `en` 或 `zh_CN`，否则按 `zh_CN` 处理。

## 与统一 JSON 响应的关系

[`response.JSON`](../internal/app/common/response/result.go) 在写入 `Result` 时：若 **`message` 恰好等于** 该 `code` 的 **`defaultMessage`（内置英文默认值）**，会把 `message` 替换为 **`i18n.T(FromGin(c), ResultMessageKey(code))`**，从而与 **`result.success`**、**`result.unauthorized`** 等键对应。自定义错误字符串通常不会被替换。

业务码与 i18n 键对照见 [`ResultMessageKey`](../internal/app/common/response/resultcode.go)。
