# 权限系统

基于 RBAC 的双权限体系：功能权限控制「能访问什么菜单」，数据权限控制「能访问谁的数据」。

```
用户 (User) → 角色 (Role) → 菜单 (Menu)            功能权限
                ↓
           data_scope → 部门 → 用户ID列表            数据权限
                ↓
        whereIn('created_by', $userIds)              最终过滤
```

## 数据库表结构

| 表名 | 关键字段 | 说明 |
|---|---|---|
| `user` | id, username, status | 用户表 |
| `role` | id, name, code, data_scope, status | 角色表（data_scope 决定数据权限类型） |
| `menu` | id, name, path, parent_id, status, meta | 菜单表（name 为权限标识） |
| `user_belongs_role` | user_id, role_id | 用户-角色关联 |
| `role_belongs_menu` | role_id, menu_id | 角色-菜单关联 |
| `role_belongs_department` | role_id, dept_id | 角色-部门关联（仅 data_scope=2 使用） |
| `user_admin_setting` | user_id, dept_id | 用户设置（dept_id 为 JSON 数组，用户所属部门） |
| `department` | id, parent_id, name | 部门表（树形结构） |

## 功能权限

### 权限模型

用户 → 角色 → 菜单。用户的权限 = 所有**正常状态**角色（status=1）的菜单集合（去重）。只有 status=1 的角色参与判断。

### Permission 注解

```php
use App\Http\Admin\Permission;

#[Permission(code: 'user.list')]                    // 方法级：需要 user.list 权限
#[Permission(code: ['user.create', 'user.edit'], operation: Permission::OPERATION_OR)]  // 任一即可
```

| 参数 | 说明 |
|---|---|
| `code` | 权限码（菜单 name 字段），字符串或数组 |
| `operation` | `OPERATION_AND`（默认，全部需要）/ `OPERATION_OR`（任一即可） |

### 权限检查

**后端**：
```php
$user = $currentUser->adminUser();
$user->hasPermission('user.list');    // bool
$user->getPermissions();              // 菜单集合（去重）
$user->isSuperAdmin();                // 超级管理员
```

**前端**：
```typescript
import hasAuth from '@/utils/permission/hasAuth'
import hasRole from '@/utils/permission/hasRole'

hasAuth('user.list')                          // 单权限
hasAuth(['user.create', 'user.edit'])         // 多权限 OR
hasRole('admin')                              // 角色检查
```

```vue
<el-button v-if="hasAuth('user.create')">新增</el-button>
```

**路由级**：
```typescript
{ path: '/user', meta: { auth: ['user.manage'], role: ['admin'] } }
```

### 中间件自动校验链

`PermissionMiddleware` 自动执行：检查用户状态 → 超级管理员跳过 → 解析 `@Permission` 注解 → 验证权限。类级和方法级注解都生效。

## 数据权限

### 五种数据范围

| data_scope | 类型 | 数据源 | 说明 |
|---|---|---|---|
| 1 | 全部数据 | 无 | 不添加过滤条件 |
| 2 | 自定义 | `role_belongs_department` | 角色配置可访问的部门 |
| 3 | 本部门 | `user_admin_setting.dept_id` | 用户所属部门 |
| 4 | 本部门及以下 | `user_admin_setting.dept_id` + 子部门 | 递归取子部门 |
| 5 | 本人 | 当前用户 ID | `where('created_by', $user->id)` |

### 优先级（从高到低）

1 > 2 > 4 > 3 > 5

多角色时取**最高权限**（不取并集）。多个 data_scope=2 角色的部门 ID 会合并去重。

### 过滤流程

```
用户请求数据
  → 获取正常状态角色
  → applyUserDataScope(0, $query)
    → 按 data_scope 优先级判断
    → 获取可访问的用户 ID 列表
      ├─ data_scope=2：role_belongs_department → 部门 ID → getUserIdsByDeptIds
      ├─ data_scope=3：user_admin_setting.dept_id → 同部门用户 ID
      ├─ data_scope=4：user_admin_setting.dept_id + getAllChildrenIds → 用户 ID
      └─ data_scope=5：当前用户 ID
    → whereIn('created_by', $userIds)
  → 返回过滤后的数据
```

核心原理：数据归属为 `created_by` 字段。先按权限范围查到可访问的用户 ID 列表，再用 `whereIn('created_by', $userIds)` 过滤。

### DataScopeTool 使用

```php
use App\Http\Admin\Service\Permission\DataScopeTool;

// 在 Repository::handleSearch 中应用
public function handleSearch(Builder $query, array $params): Builder
{
    if (Arr::has($params, 'created_by')) {
        DataScopeTool::applyUserDataScope($params['created_by'], $query);
        unset($params['created_by']);
    } else {
        DataScopeTool::applyUserDataScope(0, $query);  // 0 = 当前登录用户
    }
    return parent::handleSearch($query, $params);
}

// 角色或部门变更后清除缓存
DataScopeTool::clearCurrentUserCache($userId);
```

### getUserIdsByDeptIds 实现

查询 `user_admin_setting` 表，`dept_id` 是 JSON 数组字段，使用 `whereJsonContains` 查询属于指定部门的用户 ID。批量查询避免 N+1 问题。

## 超级管理员

拥有 `SuperAdmin` 角色代码的用户：
- 功能权限：跳过所有检查，拥有全部菜单
- 数据权限：data_scope=1，可访问所有数据

## 使用流程

1. 创建角色并设置 `data_scope`
2. 创建菜单并设置权限标识（name 字段，如 `user.list`）
3. 将菜单分配给角色（`role_belongs_menu`）
4. data_scope=2 时配置角色可访问部门（`role_belongs_department`）
5. 将角色分配给用户（`user_belongs_role`）
6. 设置用户所属部门（`user_admin_setting.dept_id`，JSON 数组）
7. 控制器用 `@Permission`，Repository 用 `DataScopeTool`

## 注意事项

- 所有需要数据权限的表必须有 `created_by` 字段
- `user_admin_setting.dept_id` 是 JSON 数组格式
- 只有 status=1 的角色和菜单参与判断
- 角色或部门变更后必须 `DataScopeTool::clearCurrentUserCache($userId)`
- 用户权限信息缓存 1 小时
