# 编码文档：翻译链路（字典 + i18n locale + 组件）

> 本文档只记录框架层规范，用于快速定位代码，避免重复检索消耗 token。
>
> 范围：字典定义 → 运行时注册 → MaDictSelect 渲染 → 标签/展示翻译 → locale 文件。

---

## 1. 分层与文件索引

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 字典定义 | `dictionary/*.ts` | 每个文件导出 `Dictionary[]`：`{ label, value, i18n, ?disabled, ?options }` |
| i18n locale | `admin/src/locales/*.yaml` | 按语言写树形翻译，key 与字典项 `i18n` 对齐 |
| 字典注册（provider） | `admin/src/provider/dictionary/index.ts` | `import.meta.glob` 扫描字典目录，注册到 `app.config.globalProperties.$dictionary[name]` |
| 字典注入 Pinia | `admin/src/bootstrap.ts` | 遍历 `$dictionary`，逐项 `dictStore.push(name, data)` |
| dictStore 核心 | `admin/src/store/modules/useDictStore.ts` | Pinia store：`find` / `t` / `push` / `append` / `remove` / `all` / `clear` |
| MaDictSelect | `admin/src/components/ma-dict-picker/ma-dict-select.vue` | 下拉组件：接收 `dictName` 或 `data`，内部 computed 预翻译 `item.i18n` |
| i18n bootstrap | `admin/src/bootstrap.ts`（`createI18nService`） | 扫描 locale 文件、`createI18nInstance()` 创建全局 vue-i18n 实例 |
| 全局 i18n 工具 | `admin/src/utils/i18n.ts` | `createI18nInstance` / `getI18n` / `useI18nGlobal` / `t` / `te` / `setLocale` |
| 组件 i18n | `import { useI18n } from 'vue-i18n'` | Vue 组件内直接使用原生 vue-i18n composable |
| 展示 label | 业务层统一 helper | 列表 / 标题 / 协议等非下拉场景的唯一翻译入口 |

## 2. 两条边界（禁止穿插）

| | JSON 字典（闭集 value） | 非字典 UI / 产品文案 |
| --- | --- | --- |
| 定义 | `dictionary/*.ts` + locale 中对应 `i18n` 路径 | locale 里的纯 UI 文案树 |
| 绑定 | `value` 进 API / DB / 筛选 | 无 value，仅展示 |
| 组件下拉 | `<MaDictSelect dict-name="xxx" />` | — |
| 代码展示 | 业务层统一 label helper | `useI18n().t('ui.xxx')` 或 `@/utils/i18n.ts` 的 `t()` |
| 禁止 | `dictStore.t` 当 label、伪造只用于展示的字典 | 把固定按钮文案写进 `dictionary/*.ts` |

判定标准：**会进 API / DB 的闭集值才建字典**；纯展示文案一律写 locale。

## 3. i18n 使用规范（两种场景，两种方式）

### 方式 A：Vue 组件 / Store setup 上下文 → `useI18n()`

**有 `<i18n>` 局部翻译块的组件：**

```ts
import { useI18n } from 'vue-i18n'
const { t } = useI18n({ useScope: 'local' })  // 优先查局部，再 fallback 到全局
```

**无局部 i18n 的组件 / Store：**

```ts
import { useI18n } from 'vue-i18n'
const { t } = useI18n()  // 全局 scope
```

> **判断依据**：文件顶部是否有 `<i18n lang="yaml">` 块。有则必须用 `useScope: 'local'`，否则局部翻译不生效。

### 方式 B：普通 .ts 文件 / 非 setup 上下文 → `@/utils/i18n.ts`

```ts
import { t, te, setLocale, getLocale } from '@/utils/i18n.ts'

// 直接调用（非响应式，用于工具函数等一次性场景）
const label = t('some.key')
```

`@/utils/i18n.ts` 还提供响应式 composable（用于 store setup 等场景）：

```ts
import { useI18nGlobal } from '@/utils/i18n.ts'

const { t, locale } = useI18nGlobal()  // 响应式 t，语言切换自动更新
```

### 已废弃：`useTrans`

`src/hooks/auto-imports/useTrans.ts` 的 `useTrans()` 已废弃，不再使用。

- `useTrans().globalTrans` → 替换为 `useI18n().t`
- `useTrans().localTrans` → 替换为 `useI18n({ useScope: 'local' }).t`

## 4. Dictionary 条目三字段

字典项结构（所有字典文件一致）：

```ts
{
  label: '默认中文',                  // i18n 取不到时的兜底硬编码
  value: 'xxx',                      // 真正绑定 API / DB / 筛选的值
  i18n: 'ui.xxx.yyy',                // 对应 locale YAML 的 key 路径
}
```

- `value`：**业务唯一真实值**，进入 type filter、API payload、DB 存储，永不翻译
- `label`：兜底硬编码中文标签，仅在 i18n 翻译不可用时显示
- `i18n`：vue-i18n 翻译 key，走 `.yaml` 中对应路径

### 命名规则

- **dictName = 字典文件名去掉后缀**（`xxx.ts` → `xxx`），大小写与连字符必须一致，否则 `dictStore.find` 取不到
- 字典文件必须放在被 glob 扫描的目录下：框架 `provider/dictionary/data/`、业务与插件目录下的 `dictionary/`、模块目录下的 `dictionary/`
- 支持 `.ts` / `.js`

### MaDictSelect 的标签渲染优先级

```ts
// translatedOptions computed 内部预计算
const label = item.i18n ? t(item.i18n) : item.label
```

**有 `i18n` → 走 vue-i18n locale 翻译；无 → 直接用硬编码 `label`。**
此规则同时适用于 `el-option-group` 的 group label 和 group 内 `sub` 项。

> **响应式说明**：翻译在 `translatedOptions` computed 中完成，`t()` 在 computed 内部被调用，locale 变化时 computed 自动重算 → 视图更新。

### MaDictSelect 取值

```vue
<el-option :value="item.value" :label="item._label">
```

`v-model` / `emit('update:modelValue', ...)` 始终绑定/发射 **`item.value`**（字符串或原始值），与 locale / 翻译完全无关。

## 5. 字典注册链路（启动加载流程）

```
启动 bootstrap
  → initProvider() 遍历 admin/src/provider/**/index.ts
    → provider/dictionary/index.ts.init()
      → import.meta.glob 扫描 3 个 glob 模式：
         ./data/**.{ts,js}                          （框架级字典）
         ../../plugins/*/*/dictionary/**.{ts,js}   （插件级字典）
         ../../modules/**/dictionary/**.{ts,js}    （模块级字典）
      → 字典文件名正则提取作为 dictName
         正则：/(data|plugins\/.*\/dictionary|modules\/.*\/dictionary)\/(.*)\.(ts|js)/ → $2
      → dictionary[name] = module.default
    → setProvider：app.config.globalProperties.$dictionary = dictionary

  → otherWorker()
    → Object.entries($dictionary).map(([name, data]) => dictStore.push(name, data))
    → Pinia dictMap.value.set(name, data) 完成注册
```

dictStore.push(name, data, replace=false)：

- 首次 push → `set` 并返回 true
- 已存在 + `replace=true` → 覆盖并返回 true
- 已存在 + `replace=false` → **跳过**（返回 false），保证后注册不覆盖先注册

## 6. 两种"查字典"方式

### 方式 A：MaDictSelect（下拉组件 UI，走 i18n）

```vue
<MaDictSelect
  v-model="preset"
  dict-name="xxx"
  filterable
  size="small"
  clearable
/>
```

**内部流程（ma-dict-select.vue）：**

1. `dictStore = useDictStore()` → `sourceData = dictName ? dictStore.find(dictName) : data`
2. `const { t } = useI18nGlobal()` → 全局翻译函数
3. `translatedOptions = computed(...)` 逐项 `_label = item.i18n ? t(item.i18n) : item.label`，分组 `options` 子项同理
4. v-for 每个 item → `:value="item.value"`（发射原值），`:label="item._label"`（预翻译结果）
5. `$attrs` 透传 `filterable` / `size` / `clearable` / `placeholder` 到底层 `el-select`

### 方式 B：代码展示字典文案 → 业务层统一 helper

```ts
import { xxxDictLabel } from '.../dictLabel.ts'

xxxDictLabel('xxx', 'value')
```

`xxxDictLabel(dictName, value)` 规范：

1. `findDictItem`：`dictStore.find` + **`options` 子项**（`dictStore.t` 无此能力）
2. `itemDisplayLabel`：有 `i18n` 且 `te(key)` → `t(key)`；否则 `item.label`；否则 `String(value)`
3. 找不到项 → `String(value)`

扩展字段（如 suffix）：先 `findDictItem` 读字段，再 `dictStore.t(..., attr)` 兜底（仅顶层项）。

**统一 helper 不冗余**：与 MaDictSelect 分工——下拉在组件内 computed 翻译；列表 / 标题 / 协议 TS 走 helper，避免在业务里散落 `dictStore.t` / 手写 `t(i18n)`。

**禁止**业务代码直接 `dictStore.t(name, value)`（label 或扩展字段均走统一 helper）。`dictStore.find` 仅用于 MaDictSelect 数据源或组装选项列表。

| | MaDictSelect | 统一 helper |
| --- | --- | --- |
| 取翻译 | `item.i18n ? t(i18n) : label`（缺 key 时可能露出 key 串） | `te(i18n) ? t(i18n) : label`（缺 key 回退 label） |
| 分组 options | 支持 | `findDictItem` 支持 |
| 多语言 | ✅ | ✅（`t()` 来自 `@/utils/i18n.ts`） |
| dict 未加载 | 空下拉 | 回退 value 字符串 |

## 7. 空列表 / 空区块文案规范（钉死）

**无数据时的说明文案只有一条 locale 键**，禁止按页面或资源类型再拆同义键。

| 场景 | 用法 | 禁止 |
| --- | --- | --- |
| 表格 `empty-text`、`el-empty` 描述、各类列表空态 | `t('ui.common.noData')` | 按业务拆 `emptyXxx` / `暂无××` / `xxxEmpty` 等同义键 |
| 操作引导（让用户去点选） | 专用键，如 `ui.xxx.selectTarget` | 与 `noData` 混用或再写一套「暂无××」 |
| 大图预览区无图时的操作说明（非列表空态） | 专用键 | 写成 `noData`（会丢失引导语义） |

```vue
<el-table :empty-text="t('ui.common.noData')" />
<div class="…__placeholder">{{ t('ui.common.noData') }}</div>
```

新增空态时：**先判断是「没有记录」还是「请用户去选」**；前者只用 `common.noData`，后者单独键且不得再以「暂无××」命名。

## 8. i18n locale 链路

### 8.1 Vue I18n 注入

`admin/src/bootstrap.ts`：

```
createI18nInstance(locale)  ←  @/utils/i18n.ts
  ↓
messages = @intlify/unplugin-vue-i18n/messages
  ↓ 构建时合并所有 locale YAML
vue-i18n createI18n({
  legacy: false,
  fallbackLocale: 'zh_CN',
  locale: useUserStore().getLanguage(),
  messages,
  globalInjection: true,
})
  ↓
app.use(i18n)
  ↓
组件内: const { t } = useI18n()
普通ts: import { t } from '@/utils/i18n.ts'
```

### 8.2 语言切换链路

```
用户点击语言切换
  → userStore.setLanguage(locale)
      → cache.set('language', locale)
      → setLocale(locale)  ← @/utils/i18n.ts，更新全局 i18n 实例
  → locale.value = locale  ← 组件内 useI18n 的 locale ref
  → 所有使用 t() 的 computed / 模板自动更新
```

> `userStore.setLanguage()` 内部会调用 `setLocale()` 同步全局 i18n 实例，确保 store 和 i18n 一致。

### 8.3 locale 文件结构

文件命名规范：`<lang_code>[<lang_label>].yaml`，bootstrap 正则提取：

```
/\/locales\/(\w+)\[([^[\]]+)\]\.yaml$/
   $1 = value （locale code），例：zh_CN
   $2 = label （展示名），例：简体中文
```

### 8.4 新增翻译的同步点

**每新增一个 key，必须同步所有语言的 locale 文件**（`admin/src/locales/` 现有 `zh_CN` / `zh_TW` / `en`）；任何独立维护 locales 的业务目录，按其语言集同样全部补齐。

**编辑约定：只改源码维护的那一份，构建产物 / 同步副本通过构建流程生成，不手改。**

**YAML 语法（改完必检）**：与 Vite 同源 `yaml-eslint-parser`。值含 `#`（如 `#{id}`）或行首 `{`（如 `{kinds}`）须加引号。校验：仓库根 `bash script/check.sh`。

### 8.5 新增字典 + 翻译的完整同步清单

```
1. dictionary/xxx.ts
      └─ 定义 { label, value, i18n:'ui.xxx.yyy' }[]
2. 所有语言 locale yaml 各加对应翻译
3. 代码展示用统一 label helper；下拉用 <MaDictSelect dict-name="xxx" />
```

## 9. 常见坑位清单

| 坑 | 表现 | 解 |
| --- | --- | --- |
| 字典 .ts 加了项但 locale yaml 没加对应翻译 | MaDictSelect 下拉显示硬编码 label | 在全部语言 locale 补 i18n key 路径 |
| dictName 拼错（大小写 / 连字符） | MaDictSelect 空下拉 + `dictStore.t` 返回 null → 回退原值 | 核对 dictionary 目录文件名（.ts 名 = dictName） |
| i18n key 路径拼错 | 翻译不生效，显示原 key 字符串 | 对照现有项核对完整 key 路径 |
| 展示文案直接用 `dictStore.t` 取 label | 标签与 MaDictSelect 不一致 | 改为统一 label helper |
| provider dict 扫描不生效（新建字典文件没被 glob 匹配） | 字典空 | 字典文件必须放在被扫描的 `dictionary/` 目录，后缀 `.ts` 或 `.js` |
| `dictStore.push` 返回 false（字典重复注册） | 后注册的字典项"不生效" | push 第三参传 `true`；或先 `dictStore.remove(name)` 再 push |
| 有 `<i18n>` 局部块但没用 `useScope: 'local'` | 局部翻译不生效，显示原 key | 改为 `useI18n({ useScope: 'local' })` |
| 语言切换后下拉选项不更新 | `t()` 没在 computed / 模板响应式上下文中调用 | 确保翻译在 computed 中计算，或模板中直接调用 `t()` |
| 在普通 ts 文件中用 `useI18n()` | 报错：必须在 setup 上下文中调用 | 改用 `import { t } from '@/utils/i18n.ts'` |
| 列表空态每种资源一个 locale 键 | 多语言维护膨胀、同义文案不一致 | 统一 `ui.common.noData`；引导类占位单独键（§7） |
