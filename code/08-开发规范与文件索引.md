# 开发规范与文件索引

## 开发规范与约束

### 后端规范

1. **分层架构**：Controller → Service → Repository → Model，严格分层调用
2. **服务独立性**：各服务函数功能独立，不可交叉调用
3. **事务原子性**：删除操作使用 `Db::transaction` 包裹
4. **参数验证**：使用 Request 类进行参数校验
5. **统一响应**：通过 `Result` 类返回统一格式

### 前端规范

1. **路径别名**：`@` 表示 `src/` 根目录，`$` 表示 `plugins/` 根目录
2. **组合式优先**：优先使用 `<script setup>` + composables
3. **状态管理**：共享状态使用 Pinia，组件内状态使用 ref/reactive
4. **无前置验证**：前端不做参数范围验证，全部交由后端处理

### 工程约束（项目记忆）

- 所有操作跳过 `admin` 目录
- 不做向后兼容
- `neutral` 情绪条目必须从前后端代码中移除
- 解剖修复图像处理必须使用 Qwen-Image-Edit 模型
- Qwen-Image-Edit 管线与 SDXL 管线完全隔离
- SDXL 提示词拼接使用统一模板（详见 AI 图像管线章节）
- SDXL 图像生成不包含抠图（BiRefNet）步骤
- VRM 模型名规范化：去除 `.vrm` 扩展名并转为大写
- modelName 为空时 PHP 必须抛出 RuntimeException
- SDXL 不再处理 `character` 类型，角色生成完全由 3D 实现
