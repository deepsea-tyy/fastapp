# 权限系统使用文档

## 系统概述

基于 RBAC（基于角色的访问控制）的权限系统，包含两大核心模块：

1. **功能权限**：控制用户可以访问哪些菜单和功能
2. **数据权限**：控制用户可以访问哪些数据范围

### 权限系统架构

```
用户 (User) → 角色 (Role) → 菜单 (Menu)
                ↓
           数据范围 (data_scope)
                ↓
        用户所属部门 (user_admin_setting.dept_id)
        角色可访问的部门数据权限 (role_belongs_department)
```

### 核心概念

| 概念 | 说明 |
|------|------|
| **用户（User）** | 系统使用者 |
| **角色（Role）** | 权限集合，包含功能权限和数据权限 |
| **菜单（Menu）** | 功能权限的最小单位，通过菜单名称（name）标识 |
| **数据范围（data_scope）** | 数据权限类型，决定用户可以访问的数据范围 |

## 功能权限系统

### 权限模型

功能权限采用 **用户 → 角色 → 菜单** 的模型：

- 用户可以被分配多个角色
- 角色可以关联多个菜单
- 用户的权限 = 用户所有**正常状态**角色的菜单集合（去重）
- 只有状态为正常（status=1）的角色才会参与权限判断

### 数据库表结构

| 表名 | 关键字段 | 说明 |
|------|---------|------|
| `user` | id, username, status | 用户表 |
| `role` | id, name, code, data_scope, status | 角色表 |
| `menu` | id, name, path, parent_id, status, meta | 菜单表（name为权限标识） |
| `user_belongs_role` | user_id, role_id | 用户角色关联表 |
| `role_belongs_menu` | role_id, menu_id | 角色菜单关联表 |
| `role_belongs_department` | role_id, dept_id | 角色部门关联表（用于自定义数据权限，表示角色可访问的部门数据权限） |
| `user_admin_setting` | user_id, dept_id | 用户设置表（dept_id为JSON数组，表示用户所属的部门）

### 权限检查机制

系统通过 `PermissionMiddleware` 中间件自动进行权限验证：
1. 检查用户状态
2. 超级管理员跳过权限检查
3. 解析控制器和方法的 `@Permission` 注解
4. 验证用户是否拥有所需权限

#### Permission 注解

```php
use App\Http\Admin\Permission;

#[Permission(code: 'user.list')]
class UserController extends AbstractController
{
    #[Permission(code: ['user.create', 'user.edit'], operation: Permission::OPERATION_OR)]
    public function create()
    {
        // 需要拥有 user.create 或 user.edit 权限
    }
}
```

**注解参数**：
- `code`: 权限码（菜单名称），可以是字符串或数组
- `operation`: 操作符
  - `Permission::OPERATION_AND`：需要拥有所有权限（默认）
  - `Permission::OPERATION_OR`：只需拥有其中一个权限

### 权限检查方法

#### 后端检查

```php
use App\Http\CurrentUser;
use App\Model\User;

// Admin控制器
$user = $currentUser->adminUser();
$hasPermission = $user->hasPermission('user.list');
$permissions = $user->getPermissions(); // 返回菜单集合（已去重）
$isSuperAdmin = $user->isSuperAdmin();

// Api控制器
$user = $currentUser->user();
$hasPermission = $user->hasPermission('user.list');
```

#### 前端检查

```typescript
import hasAuth from '@/utils/permission/hasAuth'
import hasRole from '@/utils/permission/hasRole'
import hasUser from '@/utils/permission/hasUser'

// 单个权限
if (hasAuth('user.list')) { /* 有权限 */ }

// 多个权限（OR关系）
if (hasAuth(['user.create', 'user.edit'])) { /* 有任一权限即可 */ }

// 检查角色和用户
if (hasRole('admin')) { /* 有角色 */ }
if (hasUser('admin')) { /* 是特定用户 */ }
```

### 使用示例

#### 控制器权限控制

```php
use App\Http\Admin\Permission;
use Hyperf\HttpServer\Annotation\Middleware;
use App\Common\Middleware\AccessTokenMiddleware;
use App\Http\Admin\Middleware\PermissionMiddleware;

#[Middleware(middleware: AccessTokenMiddleware::class, priority: 100)]
#[Middleware(middleware: PermissionMiddleware::class, priority: 99)]
#[Permission(code: 'user.manage')] // 类级别权限
class UserController extends AbstractController
{
    #[Permission(code: 'user.list')] // 方法级别权限
    public function list() { /* 用户列表 */ }

    #[Permission(code: ['user.create', 'user.edit'], operation: Permission::OPERATION_OR)]
    public function save() { /* 需要 user.create 或 user.edit 权限 */ }
}
```

**注意**：类级别和方法级别的权限都会生效，超级管理员自动跳过权限检查。

#### 前端权限控制

```vue
<template>
  <el-button v-if="hasAuth('user.create')" @click="handleCreate">新增用户</el-button>
  <el-button v-if="hasRole('admin')" @click="handleAdmin">管理员操作</el-button>
</template>

<script setup lang="ts">
import hasAuth from '@/utils/permission/hasAuth'
import hasRole from '@/utils/permission/hasRole'
</script>
```

#### 路由权限控制

```typescript
{
  path: '/user',
  component: Layout,
  meta: {
    auth: ['user.manage'], // 需要权限
    role: ['admin'],       // 需要角色
    user: ['admin']        // 仅特定用户
  }
}
```

## 数据权限系统

> 📖 **详细说明**：数据权限的完整实现原理、配合方式、查询逻辑等详细内容请参考 [数据权限详解](17-数据权限详解.md)

### 数据权限类型

| 类型 | 值 | 说明 | 数据源 |
|------|-----|------|--------|
| 全部数据权限 | 1 | 可访问所有数据 | 无 |
| 自定义数据权限 | 2 | 可访问指定部门的数据 | role_belongs_department（角色可访问的部门数据权限） |
| 本部门数据权限 | 3 | 只能访问本部门数据 | user_admin_setting.dept_id（用户所属的部门） |
| 本部门及以下数据权限 | 4 | 可访问本部门及子部门数据 | user_admin_setting.dept_id（用户所属的部门） |
| 本人数据权限 | 5 | 只能访问自己创建的数据 | 当前用户ID |

### 数据权限优先级

当用户拥有多个角色时，按照以下优先级确定数据权限（从高到低）：

1. **全部权限（data_scope=1）** - 最高优先级
2. **自定义权限（data_scope=2）** - 合并所有自定义角色的部门ID
3. **本部门及以下（data_scope=4）**
4. **本部门（data_scope=3）**
5. **本人（data_scope=5）** - 最低优先级

### 实现原理

数据权限基于 **数据创建者（created_by）** 进行过滤：
1. 根据角色的 `data_scope` 确定数据权限范围
2. 根据权限范围获取可访问的用户ID列表
3. 使用 `whereIn('created_by', $userIds)` 或 `where('created_by', $userId)` 过滤数据

### 使用 DataScopeTool

#### 基本使用

```php
use App\Http\Admin\Service\Permission\DataScopeTool;

// 在 Repository 中应用数据权限
public function list(array $params): Collection
{
    $query = Model::query();
    
    // 应用数据权限过滤（0 表示使用当前登录用户）
    DataScopeTool::applyUserDataScope(0, $query);
    
    // 其他查询条件
    if (isset($params['keyword'])) {
        $query->where('name', 'like', "%{$params['keyword']}%");
    }
    
    return $query->get();
}
```

#### 清除用户缓存

当用户角色或部门变更时，需要清除缓存：

```php
use App\Http\Admin\Service\Permission\DataScopeTool;

// 更新用户信息后清除缓存
User::query()->where('id', $userId)->update($data);
DataScopeTool::clearCurrentUserCache($userId);
```

### 数据权限示例

#### 自定义数据权限（data_scope=2）

```php
// 角色配置
$role = Role::create([
    'name' => '项目管理员',
    'code' => 'project_manager',
    'data_scope' => 2, // 自定义权限
]);
$role->departments()->attach([1, 2, 3]); // 配置可访问的部门

// 数据查询
$query = Project::query();
DataScopeTool::applyUserDataScope(0, $query);
// 结果：只能访问部门1、2、3下用户创建的项目
```

#### 本部门及以下权限（data_scope=4）

```php
// 用户配置：设置用户所属的部门
$user->adminSetting->dept_id = [1]; // 用户属于技术部
$user->adminSetting->save();

// 角色配置
$role = Role::create([
    'name' => '部门经理',
    'data_scope' => 4, // 本部门及以下权限
]);

// 数据查询
$query = Task::query();
DataScopeTool::applyUserDataScope(0, $query);
// 结果：可以访问技术部及其子部门下用户创建的任务
```

## 超级管理员

拥有 `SuperAdmin` 角色代码的用户为超级管理员，拥有以下权限：

- **功能权限**：跳过所有权限检查，拥有所有菜单权限
- **数据权限**：拥有全部数据权限（data_scope=1），可访问所有数据

### 检查超级管理员

```php
use App\Http\CurrentUser;

// Admin控制器
$user = $currentUser->adminUser();
$isSuperAdmin = $user->isSuperAdmin();

// 或直接使用 CurrentUser 的方法
$isSuperAdmin = $currentUser->isSuperAdmin();
```

## 代码示例

### 完整的控制器示例

```php
use App\Http\Admin\Permission;
use App\Http\CurrentUser;
use App\Repository\ProjectRepository;
use Hyperf\HttpServer\Annotation\Middleware;
use App\Common\Middleware\AccessTokenMiddleware;
use App\Http\Admin\Middleware\PermissionMiddleware;

#[Middleware(middleware: AccessTokenMiddleware::class, priority: 100)]
#[Middleware(middleware: PermissionMiddleware::class, priority: 99)]
#[Permission(code: 'project.manage')]
class ProjectController extends AbstractController
{
    public function __construct(
        private readonly CurrentUser $currentUser,
        private readonly ProjectRepository $repository
    ) {}

    #[Permission(code: 'project.list')]
    public function list()
    {
        // 自动应用数据权限（在Repository的handleSearch中）
        $data = $this->repository->list($this->getRequestData());
        return $this->success($data);
    }

    #[Permission(code: 'project.create')]
    public function create(ProjectRequest $request)
    {
        $project = $this->repository->create(array_merge($request->validated(), [
            'created_by' => $this->currentUser->id(),
        ]));
        return $this->success($project);
    }
}
```

### 完整的 Repository 示例

```php
use App\Http\Admin\Service\Permission\DataScopeTool;
use App\Repository\IRepository;
use Hyperf\Collection\Arr;
use Hyperf\Database\Model\Builder;

class ProjectRepository extends IRepository
{
    public function handleSearch(Builder $query, array $params): Builder
    {
        // 应用数据权限（0 表示使用当前登录用户）
        if (Arr::has($params, 'created_by')) {
            DataScopeTool::applyUserDataScope($params['created_by'], $query);
            unset($params['created_by']);
        } else {
            DataScopeTool::applyUserDataScope(0, $query);
        }
        
        // 处理特殊查询条件
        if (Arr::has($params, 'keyword')) {
            $query->where('name', 'like', "%{$params['keyword']}%");
            unset($params['keyword']);
        }
        
        // ⚠️ 必须调用父类方法
        return parent::handleSearch($query, $params);
    }
}
```

**要点**：
- `DataScopeTool::applyUserDataScope(0, $query)` 中的 `0` 表示使用当前登录用户
- 已处理的参数必须使用 `unset($params['key'])` 移除
- 必须调用 `parent::handleSearch($query, $params)` 应用自动搜索

## 最佳实践

### 权限设计建议

1. **菜单命名规范**：使用模块化命名，如 `user.list`、`user.create`、`user.edit`
2. **权限粒度**：为每个功能点配置独立的权限码，便于细粒度控制
3. **角色划分**：根据业务需求创建角色，避免角色过多导致管理复杂

### 数据权限设计建议

1. **数据归属**：确保所有数据表都有 `created_by` 字段
2. **部门配置**：正确配置用户所属的部门（`user_admin_setting.dept_id`）
3. **角色配置**：根据业务需求合理设置角色的 `data_scope`，自定义权限（data_scope=2）通过 `role_belongs_department` 配置角色可访问的部门数据权限
4. **缓存管理**：角色或部门变更后及时清除用户缓存

### 性能优化

1. **批量查询**：系统已优化多角色权限查询，使用批量查询避免N+1问题
2. **缓存机制**：用户权限信息缓存1小时，减少数据库查询
3. **索引优化**：确保关联表有适当的索引

## 常见问题

| 问题 | 解答 |
|------|------|
| 为什么用户看不到某些菜单？ | 检查：用户是否拥有相关角色、角色是否关联了相应菜单、菜单和角色状态是否为正常（status=1） |
| 为什么数据权限不生效？ | 检查：是否调用了 `DataScopeTool::applyUserDataScope()`、数据表是否有 `created_by` 字段、用户所属部门配置是否正确（`user_admin_setting.dept_id`）、角色的 `data_scope` 是否正确配置、自定义权限是否配置了 `role_belongs_department`、是否清除了用户缓存 |
| 多角色权限如何合并？ | 功能权限：取并集（所有正常状态角色的菜单合并，按菜单ID去重）；数据权限：按优先级取最高权限；只有状态为正常（status=1）的角色才会参与权限判断 |

## 使用流程

1. **配置角色**：创建角色并设置数据权限范围（data_scope）
2. **配置菜单**：创建菜单并设置权限标识（name字段）
3. **关联权限**：将菜单分配给角色（通过 role_belongs_menu 表）
4. **配置部门**（可选）：如果角色是自定义权限（data_scope=2），需要配置角色可访问的部门数据权限（通过 role_belongs_department 表）
5. **分配角色**：将角色分配给用户（通过 user_belongs_role 表）
6. **配置用户部门**：设置用户所属的部门（user_admin_setting.dept_id）
7. **应用权限**：在控制器使用 `@Permission` 注解，在 Repository 使用 `DataScopeTool`

## 注意事项

1. **数据表要求**：确保所有需要数据权限控制的数据表都有 `created_by` 字段
2. **用户部门配置**：正确配置用户所属的部门（`user_admin_setting.dept_id`，JSON数组格式）
3. **角色部门配置**：自定义权限（data_scope=2）通过 `role_belongs_department` 表配置角色可访问的部门数据权限
4. **角色状态**：只有正常状态（status=1）的角色才会参与权限判断
5. **菜单状态**：只有正常状态（status=1）的菜单才会被返回
6. **缓存管理**：角色或部门变更后及时清除用户缓存（`DataScopeTool::clearCurrentUserCache($userId)`）
7. **权限注解**：使用权限注解时注意操作符的选择（AND/OR）
8. **超级管理员**：拥有 `SuperAdmin` 角色代码的用户自动拥有所有权限，跳过权限检查
